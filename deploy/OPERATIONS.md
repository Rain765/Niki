# Niki 长期运行与存储规范

适用范围：Mac mini 上的 Niki 本地部署、开发副本与任务收尾。更新日期：2026-09-27。

## 保留哪些目录

- 正式运行目录由 `~/.local/share/niki-runtime/current` 指向。保留当前发布及上一个可回滚发布的完整依赖和运行文件。发布切换后先验证新实例，再处理更旧的发布。
- 主源码仓库保留；临时 Git worktree 用于隔离任务。任务完成且变更已纳入交付版本后，按下述检查移除副本，不长期保留每份副本的依赖和构建产物。
- 正在运行、仍承担测试服务、包含未交付提交或任务状态不明的副本保留。Codex 管理的副本还需确认对应任务不再使用；没有进程不等于任务已结束。
- 本地数据库、上传内容、生成作品、凭据、环境配置和验证记录不是缓存。旧备份中的这些内容也不能因“可以重新安装”而删除。

## 任务结束时的清理检查

用户已授权按这些条件进行常规收尾，不必逐次确认可重建文件的清理；条件不满足时保留并说明原因。

1. 记录副本路径、分支、完整 HEAD、任务用途及当前发布。确认目标是已登记的临时 worktree，解析真实路径，排除主仓库、当前工作目录、正式发布与回滚目录。
2. 确认任务完成，并证明提交已纳入明确的交付版本，例如用 `git merge-base --is-ancestor <HEAD> <delivered-commit>`。保留分支；若采用压缩合并等方式导致祖先检查不通过，需另行核对交付证据，不能仅凭目录名称或时间删除。
3. 检查进程参数、工作目录、打开的文件、开发服务、启动项和运行配置的路径引用。若有消费者仍在使用，保留。需要结束本任务的临时服务时，通过 `corepack pnpm tools-dev stop --namespace <name>` 精确停止后再检查。
4. 检查已跟踪改动、未跟踪文件和被忽略文件。Git 状态干净不代表目录没有数据。存在未提交源码或用途不明文件时，保留副本，或先完成经过验证的数据保全。
5. 只将明确的依赖和构建输出视为可重建内容，如 `node_modules`、包构建的 `dist`、确认归属的 Next 构建目录及 TypeScript 增量缓存。`.tmp` 可能含数据库、截图和验证材料，不能整体按缓存删除。
6. 将需要保留的本地数据移到仓库外的受限备份目录，例如 `~/Backups/Niki/worktree-retired/<date>/<name>/`。保存清单：原路径、分支、HEAD、归档项目、执行结果和恢复办法。凭据和数据库不得提交到 Git，清单不得包含其内容。归档没有自动过期删除期限。
7. 移除前再次检查进程和 Git 状态，使用 `git worktree remove <path>`，不用 `--force`。失败时保留、恢复已移动数据或明确记录其位置，查明原因后再处理。禁止用 `rm -rf` 删除整个副本或用 `git clean -fdx` 绕过检查。
8. 复核工作树登记、归档清单和正式服务健康，报告保留项及原因。保留分支与提交记录；不自动删除分支或改写历史。

恢复时根据清单执行 `git worktree add <new-path> <branch-or-commit>`，再将需要的数据放回原有相对路径。只有确需继续开发时才安装依赖。已有分支正在别处检出时，选用记录的提交建立 detached worktree，避免移动正在使用的分支。

## 验证和空间预算

- 缓存清理后验证日常应用及正式运行实例。不要为验证清理效果而给每个旧副本重新安装依赖。
- 必须验证历史代码时，只恢复一个副本，使用独立 namespace、端口和测试数据目录。验证结束停止临时服务，并按上述检查清理副本；保留必要的结果和截图。
- 在任务收尾、发布后和存储告警时检查空间。可用空间低于 20 GiB 时优先整理已完成任务；低于 10 GiB 时，先处理空间问题，再启动大量下载、依赖安装或打包。这是本机运维预算，不是删除用户数据的授权。
- 同时记录目录占用和文件系统实际可用空间。APFS 共享块和 Time Machine 快照可能使两者不同；不得把目录体积直接报告为实际释放空间，也不因占用未立即下降而自动删除快照。

## 发布与远程连接边界

- `deploy/scripts/niki-runtime-release-gc.zsh` 是发布目录专用回收逻辑，不能用作普通任务副本的通用清理器。当前发布和回滚发布始终先于空间回收受到保护。
- 开发服务统一使用 `corepack pnpm tools-dev`。运行中的部署以 `current`、进程来源和实际 HTTP 响应核验，不以当前终端所在的 Git 分支推断。
- Mac mini 的 Codex 远程连接由桌面应用独占提供。常规维护和升级不启用第二个 standalone remote provider；继续遵守个人 `AGENTS.md` 的远程连接所有权规范。
- 本文规定任务收尾和人工维护的执行方式；未配置定时删除任务。新增后台清理应另行明确其范围、触发条件和恢复机制。
