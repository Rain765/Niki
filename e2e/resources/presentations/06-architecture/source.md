# 订单平台架构

> 合成评测材料。机构、人物和数字均为虚构，仅用于测试文档转 PPT。

## 节点和信任边界

| 层 | 节点 | 信任边界 |
| --- | --- | --- |
| 客户入口 | 客户端 | 边界外 |
| 接入层 | API 网关 | 边界内 |
| 身份层 | 身份服务 | 边界内 |
| 业务层 | 订单服务 | 边界内 |
| 业务层 | 库存服务 | 边界内 |
| 业务层 | 支付适配器 | 边界内 |
| 异步层 | 事件总线 | 边界内 |
| 数据层 | 订单数据库 | 边界内 |
| 数据层 | 缓存 | 边界内 |
| 可观测层 | 日志平台 | 边界内 |
| 外部系统 | 支付渠道 | 边界外 |
| 异步层 | 补偿任务 | 边界内 |

## 有向连接清单

客户端 → API 网关：HTTPS / 同步。

API 网关 → 身份服务：令牌校验 / 同步。

API 网关 → 订单服务：请求路由 / 同步。

订单服务 → 库存服务：预占库存 / 同步。

订单服务 → 支付适配器：发起支付 / 同步。

支付适配器 → 支付渠道：渠道请求 / 同步。

支付渠道 → 支付适配器：支付回调 / 异步。

订单服务 → 订单数据库：事务写入。

订单服务 → 缓存：读取热点状态。

订单服务 → 事件总线：发布订单事件 / 异步。

事件总线 → 补偿任务：失败事件 / 异步。

补偿任务 → 库存服务：释放预占库存 / 幂等。

补偿任务 → 订单服务：更新补偿结果 / 幂等。

API 网关 → 日志平台：脱敏访问日志。

## 约束

只有订单服务直接写订单数据库；支付渠道不能直接访问内部数据库。事件总线采用至少一次投递，消费者必须幂等；这不等于恰好一次。支付回调先验证签名，再更新订单状态。缓存不是唯一事实来源。

## 容灾

目标 RTO 为 15 分钟，目标 RPO 为 5 分钟。补偿任务失败进入人工复核，不允许无限重试。总览图须表现所有 12 个节点，细节页可以分层拆解。
