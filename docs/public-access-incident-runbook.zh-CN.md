# 公网访问故障处理规范

当 Niki 公网地址在浏览器、飞书或其他内嵌网页客户端中无法打开时，使用本规范。本规范只处理传输链路与客户端路径故障，不授权删除应用数据或修改产品代码。

English version: [Public-access incident runbook](public-access-incident-runbook.md).

## 安全红线

- 变更前先保留证据：访问地址、时间、客户端错误、运行时命名空间、源码工作树、分支、`HEAD`、进程状态、DNS 结果、代理模式和相关日志。
- 传输错误不是存储问题。修复公网连接时，禁止删除工作树、仓库、`.od/`、数据库、缓存、凭证或用户文件。
- 命令、日志、工单和对话中不得暴露代理密码、Cookie、OAuth code/state、会话令牌或应用密钥。
- 修改任何配置前先创建带时间戳的备份。变更必须限定到具体域名，先校验语法，优先热加载，并记录可执行的回滚方式。
- 在只读探测证明某条路径可用之前，不得强制域名走 `DIRECT`、代理或指定地址。

## 先确认用户实际访问的运行实例

开始诊断前，必须确认：

1. 用户入口是公网 URL、桌面应用、浏览器还是内嵌客户端。
2. 运行时命名空间、daemon/web 端口、源码工作树、分支和 `HEAD`。
3. 公网域名以及预期的入口转发方式。
4. 当前系统代理模式、命中的代理规则和实际 DNS 解析器。

开发运行时可先执行：

```sh
pnpm tools-dev status --json
git worktree list
git branch --show-current
git rev-parse HEAD
```

不得假设当前终端所在工作树就是用户正在使用的运行实例。

## 按层排查

每次使用新连接并记录时间。命令中的占位符只在本机替换，严禁填入并粘贴任何密钥。

| 层级 | 只读检查 | 成功能够证明 |
| --- | --- | --- |
| 本机应用 | `curl -fsS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:<web-port>/` | web 进程在本机能够返回入口文档。 |
| 私网入口 | `curl --noproxy '*' --resolve <host>:443:<private-ip> -I https://<host>/` | 私网路由、SNI、证书和入口转发能够到达应用。 |
| 公网直连 | 分别用当前 DNS 和独立 DNS 查询，再执行 `curl --noproxy '*' -Iv --max-time 15 https://<host>/` | 当前网络不经代理可以建立公网 TLS。 |
| 代理路径 | `curl -x http://127.0.0.1:<proxy-port> -Iv --max-time 30 https://<host>/` | 所选代理线路可以建立 TLS 并收到 HTTP。 |
| 实际报错客户端 | 新建浏览器标签页，或通过官方内嵌客户端入口强制刷新。 | 实际客户端、代理归属、页面资源和渲染路径能够协同工作。 |

以第一处失败边界为准判断：

- 本机失败：检查托管运行时和应用日志，暂时不要改公网路由。
- 本机成功、私网入口失败：检查私网隧道、serve 映射、SNI 和证书。
- 私网入口成功、公网直连 TLS 被关闭、代理成功：定性为直连路由与边缘入口的交互故障，不能说公网服务整体宕机。
- 传输探测全部成功、实际客户端失败：检查客户端代理归属、DNS/缓存状态、内嵌客户端策略和实际启动链接。
- 所有路径都失败：取得服务器或边缘侧遥测后，才能把根因归到外部服务商。

`ERR_CONNECTION_CLOSED` 只表示页面加载前连接被关闭，无法单独区分应用停机、DNS、TLS、入口转发、路由、代理或客户端容器问题。

## 只做最小且可回滚的变更

从第一处失败边界开始处理：

1. 为准确的配置文件创建带时间戳的备份。
2. 只修改故障域名或对应的服务映射。
3. 校验配置语法并重新加载所属进程。
4. 强制建立新的 TCP/TLS 连接；复用旧连接不算验证。
5. 重测故障层，然后依次验证所有下游层级。
6. 如果实际客户端仍失败，先回滚，再验证下一个假设。

除非更小范围的证据证明有必要，否则不要修改全局代理模式、全局 DNS、证书例外、`/etc/hosts`、浏览器启动参数，也不要重装应用或删除缓存。清缓存只是客户端状态实验，不能替代传输诊断；处理可恢复的客户端状态前也要先备份。

## 必须在实际报错客户端中验收

命令行请求只能作为诊断证据，不能代替最终验收。

浏览器验收需保留当前时间的 URL 和页面标题或等价截图，并确认浏览器进程通过预期线路建立连接。飞书验收使用官方 AppLink，并带 `reload=true`：

```text
https://applink.feishu.cn/client/web_app/open?appId=<app-id>&mode=appCenter&reload=true
```

飞书验收至少需要主 HTML、必要的 CSS/JavaScript 资源请求成功，并出现 first paint 或等价的页面就绪信号。协议说明见[飞书官方 AppLink 文档](https://open.feishu.cn/document/common-capabilities/applink-protocol/supported-protocol/open-an-h5-app?lang=zh-CN)。

## 故障记录模板

在任务或故障记录中写明：

- 用户看到的症状、客户端、URL 和首次发生时间。
- 活跃运行时命名空间、工作树、分支、`HEAD` 和端口。
- 本机、私网、公网直连、代理及实际客户端五层结果。
- 有证据支持的触发故障，以及本机配置是否放大了故障。
- 修改过的文件、带时间戳的备份、加载动作和回滚结果。
- 最终实际客户端证据，以及仍无法确认的部分。

结论必须准确。例如，“当前网络的公网直连 TLS 被关闭，而配置的代理线路成功”属于已有证据；“外部服务商宕机”则必须有服务商或边缘侧遥测支持。
